# 维护表情映射

在项目根目录运行（需要 Node.js 18 或更新版本）：

```sh
npm run edit-mappings
```

打开终端显示的地址，默认是 `http://127.0.0.1:4174/mapping-editor.html`。端口被占用时可用 `PORT=4175 npm run edit-mappings`。

1. 点击「语义 × 平台」对应的单元格。
2. 浏览该平台全部素材，或搜索名称、关键词；悬停或用键盘聚焦候选图可放大预览。
3. 点击表情即选用并关闭弹窗，也可点击「清空当前映射」。允许不同语义复用同一张图。
4. 点击「保存到本地」，将修改写入根目录的 `semantic-mappings.json`。刷新官网即可查看；发布仍需提交并推送项目。

粉色标记表示未保存项。离开页面前会提醒保存。若文件已被其他窗口或工具修改，保存会被拒绝，当前选择仍留在页面中；先记下这些选择，再刷新核对。不要用刷新来解决普通的连接错误，恢复本地服务后可以重试保存；若服务重启导致凭证失效，则需先记下选择再刷新。

维护服务仅监听本机。GitHub Pages 上的官网继续作为静态页面运行，不提供写入接口。

## 数据来源

- `emoji.json`：素材目录，包含平台、图片路径、名称和搜索标签。
- `semantic-mappings.json`：语义定义及平台图片映射。官网和维护页共同读取这一份数据。
- `config.html`：原有素材标签编辑器，与语义映射维护分开使用。

映射文件中的每个 `semantics` 条目包含 `key`、`emoji`、`label` 和 `mappings`。`mappings` 以平台 ID 为键，值为素材目录内的相对图片路径，或 `null`（暂未映射）。初始数据继承原首页的对应关系，尚未逐项人工校准；空项也不代表该平台一定没有合适的素材。

后续 AI 或适配工具应直接读取这里的明确映射，不再根据图片名称自行推断。遇到 `null` 时应保留原 emoji 或使用实现自身明确约定的回退方式，不自动填入其他图片。各实现的图片格式转换和打包规则仍由对应实现维护。

第一版维护页只允许修改图片映射；语义定义、平台定义不在页面内编辑。

验证保存与校验逻辑：

```sh
npm run test:mappings
```

## 表格内候选

仅空项会在灰底单元格中展示最多 3 张候选图，可以直接点选。选中后候选收起，只显示所选表情；仍需点击「保存到本地」。点击上方当前表情或「更多…」可浏览该平台全部素材。

候选按明确的表情名称及近义词推荐，不代表已经人工确认。候选不足时不强行补满；没有推荐的单元格仍可从完整素材库中选择。候选规则位于 `assets/mapping-candidates.mjs`，与已经保存的正式映射分开维护。
